Sommaire

Introduction

Asterism montre la configuration IA de ton ordinateur sous forme de cartes et d'une carte : quels agents de programmation sont installés, quels modèles de langage ils utilisent — services cloud et moteurs locaux —, quels modèles ceux-ci servent et quels serveurs MCP et skills chaque agent possède. Et il te permet de modifier cette configuration en dessinant des lignes.

La fenêtre principale : la carte sur toute la largeur, au-dessus la carte GPU, dans l'en-tête le ! des problèmes ouverts.

Ce qu'il fait

  • Agents de programmation — Claude Code, Codex, GitHub Copilot, Cursor CLI, Gemini, OpenCode, Pi, Hermes et d'autres : leur version, leur abonnement, leurs limites et leur utilisation, et ce qui manque à chacun, avec la commande qui le corrige.
  • LLM locaux — llama.cpp, Ollama, LM Studio, vLLM, Jan et KoboldCpp : les installer, télécharger des modèles, régler la taille de contexte qui tient dans ta carte graphique et les démarrer avec les agents qui les utilisent.
  • Serveurs MCP et skills — trouvés sur ton ordinateur ou sur le web, avec des serveurs recommandés et une recherche dans le registre MCP officiel.
  • Problèmes ouverts — un ! dans l'en-tête quand il y a quelque chose à corriger, chaque problème avec le chemin vers l'endroit où il se corrige, et ce à quoi sert ta configuration.

Notions clés

Agent
Un programme avec lequel tu parles et qui écrit du code ou fait des tâches, comme Claude Code.
Fournisseur de LLM
L'endroit où tourne le modèle d'un agent : un service cloud (Anthropic, OpenAI, …) ou un moteur de LLM local sur cet ordinateur (llama.cpp, Ollama, …).
Modèle
Le modèle de langage lui-même. Les modèles locaux sont des fichiers, le plus souvent au format GGUF.
Serveur MCP
Un petit programme ou service web qui donne des outils supplémentaires aux agents — lire des fichiers, chercher sur le web, piloter un navigateur. MCP est le Model Context Protocol.
Skill
Un dossier d'instructions (un SKILL.md) et parfois de scripts, qui apprend à un agent une tâche précise.

Rien ne change sans aperçu

Chaque modification des réglages d'un agent est d'abord montrée, ligne par ligne, avant que quoi que ce soit ne soit écrit. L'ancien fichier est gardé en sauvegarde, et la barre qui apparaît après la modification propose Annuler. L'app elle-même ne tourne jamais avec des droits d'administrateur ; seule l'installation d'un agent fourni comme paquet du système demande ton mot de passe, dans un terminal que tu vois.

Installation

Asterism Asterism

Choisis l'une de ces méthodes :

  • Arch Linux (AUR) : installe le paquet asterism avec ton assistant AUR.
  • AppImage : télécharge Asterism-<version>-x86_64.AppImage depuis la page des versions sur github.com/uBruckhaus/Asterism, rends-le exécutable et lance-le. L'AppImage utilise le Python 3 de ta distribution avec PyGObject, GTK 4 et libadwaita :
    Fedorasudo dnf install python3-gobject gtk4 libadwaita
    Ubuntu / Debiansudo apt install python3-gi gir1.2-gtk-4.0 gir1.2-adw-1
    Archsudo pacman -S python-gobject gtk4 libadwaita
  • Depuis le code source : lance bin/asterism dans un clone du dépôt.

L'app apporte ses propres icônes, aucune police d'icônes n'est donc nécessaire. Pour faire tourner des agents dans la fenêtre, installe aussi VTE pour GTK 4 (vte4).

AI Agents Map sur Omarchy Omarchy

Installe le plugin depuis l'Omarchy Plugin Marketplace ou dans un terminal :

omarchy plugin add https://github.com/uBruckhaus/omarchy-ai-agents-map.git --enable

Un bouton robot apparaît dans la barre. Tout le reste dont il a besoin est fourni par une installation normale d'Omarchy. Pour faire tourner des agents dans la fenêtre, installe VTE : sudo pacman -S vte4.

Premier démarrage

À la première ouverture, l'app demande si elle doit s'ajouter au lanceur d'applications. Rien n'y est écrit sans ton accord ; tu peux changer cela plus tard dans Réglages › Dans le lanceur.

La fenêtre est une fenêtre d'application normale : elle peut être en mosaïque, flottante, déplacée vers un autre espace de travail et atteinte avec Alt+Tab. Asterism Un Asterism neuf s'ouvre sur sa page d'accueil : les agents et LLM locaux installés sur cet ordinateur sont des cartes déjà cochées, et Activer les met sur la carte (voir Configurer Asterism). Omarchy Le bouton de la barre ouvre la fenêtre, la ramène au premier plan ou la masque si elle y est déjà. Fermer masque la fenêtre ; le programme continue en arrière-plan pour se rouvrir aussitôt.

Remarque Quand un agent tourne dans la fenêtre, la fermeture demande d'abord : Arrêter et fermer (ce qui arrête aussi le LLM local de l'agent et libère sa mémoire graphique) ou Laisser tourner.

Désinstalle d'abord un LLM local (clic droit › Désinstaller…) si tu veux qu'il disparaisse. Pour supprimer aussi l'état propre de l'app :

Configuration

La carte ne montre que ce qui est configuré : les agents et LLM locaux installés, les serveurs MCP et dossiers de skills que les agents utilisent, et les modèles. Tout le reste se fait dans Configuration (le bouton de l'en-tête à côté de Carte), une carte par élément, dans des sections qui se replient d'un clic sur leur barre :

  • Comment les éléments arrivent sur ta carte — une carte repliée tout en haut ; ouvre-la pour cinq étapes numérotées : activer (ou trouver) ce que tu utilises, installer ce qui manque, te connecter à un agent en ligne, relier en dessinant, et ce qui apparaît tout seul.
  • Ce que tu peux en faire — ce à quoi sert la configuration (aide au quotidien, programmation, images, voix, recherche et écriture), une tuile chacun avec ce qui est là et l'étape suivante ; repliée, sa ligne dit combien sont prêts.
  • Agents IA, LLM locaux — tous ceux que l'app connaît. Une carte à bordure bleue est installée sur ce PC ; une grise ne l'est pas, et elle a Installer là où les installées ont Désinstaller. Omarchy Un clic sur une carte installée ouvre ses détails. Asterism Un clic coche ou décoche la carte (✓), puis Appliquer active ou désactive son module. Désactiver la retire de la carte ; rien n'est supprimé.
  • Fournisseurs en ligne Asterism — le module des fournisseurs en ligne ; son menu propose Se connecter à … pour chaque agent installé qui les utilise.
  • Serveurs MCP, Skills, Modèles — une carte pour chaque élément installé. Un clic ouvre ses détails (pour un modèle, son menu). La carte + à la fin d'une section en ajoute un : Ajouter un serveur MCP, Ajouter des skills, Ajouter un modèle, Obtenir des extensions.
  • ⋯ ou un clic droit sur une carte ouvre le même menu que sa boîte sur la carte : mettre à jour, se connecter, démarrer ou arrêter, détails, désinstaller ou retirer, déplacer un modèle.
  • Un ↑ version jaune sur une carte signifie qu'une mise à jour est prête ; son menu propose Mettre à jour.
  • Un ! rouge sur une carte signale un problème ouvert à cet endroit ; survole-le pour savoir lequel.
  • Une petite batterie sur la carte d'un agent en ligne montre ce qui reste de ses limites (une session, une semaine) : la plus serrée compte, jaune à un quart ou moins, rouge sous un dixième ; survole-la pour chaque limite et sa remise à zéro. Sur la carte d'un LLM local en marche, la batterie est la mémoire GPU encore libre, avec les mêmes couleurs ; survole-la pour voir combien ce LLM local en utilise.
  • Le symbole d'actualisation (F5) à droite du titre regarde à nouveau ce qui est installé, configuré et connecté.

Configuration : les agents installés ont un cadre bleu, ceux activés un ✓, les mises à jour un badge jaune et les problèmes un rouge ; le menu de Claude Code.

Il n'y a rien à masquer : ce que tu ne veux pas sur la carte se désactive ou se retire ici. Quand une installation ou une connexion tourne dans un terminal dans la fenêtre, Retour (ou × sur son onglet) ramène à la page d'où elle est partie.

Choisir ce que montre la carte

La carte montre tout ce qui est configuré. Les interrupteurs Afficher sous la carte GPU laissent de côté des zones entières — par exemple toutes les skills, ou les LLM locaux et leurs modèles — et sont mémorisés.

Dans une fenêtre étroite (la moitié de l'écran ou moins), la carte les choisit elle-même, et une ligne à côté des interrupteurs le dit : tant qu'un agent tourne, agents et fournisseurs (qui travaille par quoi) ; tant qu'aucun ne tourne, fournisseurs et modèles. Un interrupteur cliqué là reste jusqu'à ce que cela change et n'est pas mémorisé ; la fenêtre en taille réelle garde ton propre choix.

Travailler avec la carte

  • Survole une boîte pour la mettre en évidence avec tout ce qui y est relié.
  • Clique sur une boîte pour la sélectionner (✓) ; Maj+clic en ajoute d'autres. Échap ou Effacer la sélection l'efface.
  • L'épingle en haut à droite d'une boîte garde ses connexions en évidence pendant que tu regardes ailleurs.
  • Clic droit sur une boîte pour tout ce que propose sa carte dans Configuration : démarrer ou arrêter, détails, installer, se connecter, modèles, mettre à jour, retirer et plus.
  • ▶ dans la boîte d'un agent le démarre dans un terminal dans la fenêtre.
  • Les agents restent toujours au centre de la partie visible de la carte pendant le défilement.
  • Le chemin actif de chaque agent — agent → le fournisseur qu'il utilise → son modèle — est dessiné en gras. Pendant qu'un agent travaille, une lumière parcourt cette ligne.
  • Une ligne rouge en pointillés relie un agent à un fournisseur pour lequel il est configuré mais qu'il n'utilise pas en ce moment (aucun de ses modèles en usage).
  • La boîte d'un agent en ligne a la même batterie que sa carte dans Configuration : ce qui reste de ses limites ; la boîte d'un LLM local en marche, la mémoire GPU encore libre.
  • Quand un programme absent de la carte utilise un LLM local, la ligne de ce LLM vers son modèle devient épaisse et prend sa propre couleur (violet ou cyan, celle qui ressort le mieux des autres couleurs du thème), et une lumière la parcourt. Voir Utilisé par d'autres apps.
  • Le symbole d'actualisation (F5) à droite du titre regarde à nouveau ce qui est installé, configuré et connecté.
  • Tant que la première ligne n'est pas tracée, une carte au-dessus de la carte montre comment en trois étapes ; Voir comment lance l'animation de l'Aide. Après la première connexion, ou avec ×, elle disparaît pour de bon.
  • Zoom avec − 100 % +, Ctrl+molette ou Ctrl++ / − / 0.

Astuce Dans une fenêtre étroite (moins d'environ 1300 pixels, à peu près un demi-écran), la carte défile latéralement.

Problèmes ouverts

Quand il y a quelque chose à corriger, un ! rouge apparaît parmi les symboles de l'en-tête ; son info-bulle dit combien, par exemple 2 problèmes ouverts · 4 suggestions. Un clic ouvre Problèmes ouverts : une ligne chacun — un agent non connecté, un LLM local sans modèles, une liaison qui ne fonctionne pas, peu de place libre pour les modèles — avec un bouton vers l'endroit où il se corrige (les détails de l'agent ou du LLM local, la carte avec cette ligne mise en évidence, Configuration, Ranger). Les mêmes problèmes apparaissent comme un ! rouge sur leurs cartes dans Configuration. Les conseils et ce qui fonctionne se trouvent sur les cartes et pages de détails elles-mêmes, et ce à quoi sert la configuration est dans Configuration (Ce que tu peux en faire). La vérification ne fait que lire ; elle ne modifie, ne démarre et n'envoie jamais rien, et ne montre rien tant que la carte est vide.

Mises à jour et suggestions

Sous les problèmes, sur la même page, Mises à jour et suggestions liste ce qu'il y a à dire : de nouveaux programmes ou skills sur ce PC, ce qui est sur ce PC mais pas sur la carte, et les mises à jour des agents et LLM locaux installés, chacun avec son bouton (Ajouter un serveur MCP…, Configuration, Mettre à jour). Quand il n'y a que celles-ci et aucun problème, le ! de l'en-tête prend la couleur d'accent. Les mises à jour sont cherchées en arrière-plan à l'ouverture de la fenêtre, au plus toutes les six heures. La recherche elle-même n'installe rien ; une mise à jour ne commence que quand tu cliques sur Mettre à jour.

Agents

Les détails d'un agent

Chaque agent de programmation a une carte dans Configuration, les installés avec leur version. Clique sur la carte d'un agent installé (Asterism ou ⋯ › Détails), ou clic droit sur sa boîte de la carte › Détails. En haut, une ligne dit si l'agent est prêt (et sinon pourquoi) et s'il tourne en ce moment ou quand il a servi pour la dernière fois. En dessous, chaque partie est une carte repliable : un clic sur son titre l'ouvre ou la ferme. Elles commencent repliées, chacune avec un résumé d'une ligne et des badges ; une partie que tu ouvres reste ouverte sur les pages de détails suivantes.

Démarrer et arrêter des agents

  • ▶ dans la boîte de l'agent ou Lancer ici dans son menu démarre l'agent dans un terminal dans la fenêtre, à la place de la carte. Cela nécessite VTE (vte4).
  • Lancer dans un terminal l'ouvre dans sa propre fenêtre de terminal.
  • Pendant qu'il tourne dans la fenêtre : Afficher le terminal et Arrêter. Arrêter met fin à l'agent et à tout ce qu'il a démarré, comme ses serveurs MCP.

Quand des agents ont des terminaux dans la fenêtre, une rangée d'onglets au-dessus de la carte montre un onglet par terminal, avec un point pour travaille, tourne ou terminé. Un clic sur un onglet affiche ce terminal ; × ferme un terminal terminé.

Un agent ouvert n'importe où sur l'ordinateur reçoit un point vert et tourne, et la boîte du modèle avec lequel il tourne indique utilisé · <agent>.

AI Playground

Les échecs et d’autres tests avec vos agents se trouvent dans une app à part : AI Playground. Un agent y joue aux échecs contre vous (ou deux agents l’un contre l’autre), on y compare vitesse et coût, on juge deux réponses à l’aveugle, on teste des images et des images de vidéo et on interroge vos LLM locaux. Elle utilise les agents configurés ici.

Quand AI Playground est installé (le plugin Omarchy, ou l’app ai-playground sur d’autres bureaux), son bouton, une manette, apparaît dans l’en-tête. Sélectionnez d’abord un agent sur la carte, et AI Playground s’ouvre avec cet agent choisi. Sous Omarchy, la page ⓘ Information en dit plus et mène à sa page dans l’Omarchy Plugin Marketplace.

Se connecter

Se connecter… dans le menu d'un agent (dans Configuration ou sur la carte) montre ce dont l'agent a besoin et ses propres façons de se connecter :

  • Un abonnement ou un compte — la connexion propre à l'agent tourne dans un terminal dans la fenêtre (par exemple claude auth login ou codex login). Ton mot de passe ou la connexion dans le navigateur restent entre toi et l'agent ; l'app ne les voit jamais. Quand l'agent le demande, le terminal dit quoi taper (Pi et Copilot : /login).
  • Une clé API — pour les agents qui en lisent une : la clé va dans un champ mot de passe, puis directement dans la propre commande de l'agent (Codex la stocke lui-même) ou dans le fichier que lit l'agent (Gemini : ~/.gemini/.env, lisible par toi seul). Elle n'atterrit jamais dans une ligne de commande, un journal ou les réglages de l'app, et l'app ne la garde pas. La facturation API de Claude Code est sa propre connexion à l'Anthropic Console, donc aucune clé ne passe par l'app.

Se connecter à Claude Code : un abonnement ou la facturation API, tous deux avec la connexion propre à Claude Code.

Ensuite, la carte montre le fournisseur en ligne de l'agent et ses modèles.

Mettre à jour des agents

Quand une version plus récente d'un agent installé existe, sa carte dans Configuration reçoit un ↑ version jaune, et Mises à jour et suggestions (le ! de l'en-tête) la mentionne. Mettre à jour lance la mise à jour de la façon dont l'agent a été installé — par exemple mise upgrade <outil> ou claude update — dans sa propre fenêtre de terminal pour que tu puisses la suivre.

Agents que l'app peut installer

Trois agents peuvent être installés, mis à jour et désinstallés depuis la carte (clic droit sur l'agent › Installer…) :

  • DeepSeek Harness (dsh, aperçu pour développeurs), depuis npm. Il peut utiliser des LLM locaux.
  • Antigravity CLI (agy, Google), depuis le manifeste de versions de Google ; le téléchargement est vérifié avec sa somme SHA-512.
  • LM Studio Bionic ne peut pas être installé d'ici (aucune somme de contrôle publiée) ; récupère-le sur lmstudio.ai. Il utilise toujours le moteur et les modèles de LM Studio.

Nouveaux agents

Quand un agent que l'app ne connaît pas encore apparaît, elle demande une fois à un agent installé (Claude Code, sinon Codex) de chercher sur le web où cet agent range ses skills et ses serveurs MCP. La réponse est vérifiée avant d'être utilisée, et rien de ce qu'elle contient n'est jamais exécuté. Réglages › Rechercher les nouveaux agents désactive cela.

LLM locaux

Un moteur de LLM local fait tourner des modèles de langage sur ta propre carte graphique, si bien que les requêtes ne quittent jamais l'ordinateur. L'app les installe, les démarre et les arrête pour toi.

Installer un LLM local

Clic droit sur un LLM local gris (non installé) de la carte › Installer…. Tu choisis le dossier du programme, le dossier des modèles (celui de tes autres LLM locaux est proposé) et s'il démarre à l'ouverture de session. Il est installé pour ton utilisateur seulement, avec un service utilisateur, donc aucun mot de passe n'est nécessaire. Chaque téléchargement doit correspondre à la somme SHA-256 publiée par sa version avant d'être décompressé ou exécuté.

MoteurRemarques
OllamaLa version officielle (avec ROCm pour les cartes AMD).
llama.cppLa compilation de ton choix (Vulkan, ROCm, CUDA, CPU), comme routeur de modèles : n'importe quel GGUF du dossier des modèles, un seul chargé à la fois.
LM StudioPas installé d'ici (aucune somme de contrôle publiée) ; récupère-le sur lmstudio.ai. Une fois installé, il est affiché et géré.
vLLMPour les cartes NVIDIA, dans son propre environnement Python.
JanSon AppImage, décompressé, avec le moteur de Jan comme service d'arrière-plan pour les agents.
KoboldCppLa compilation officielle en un seul fichier, comme routeur de modèles.

Installé ainsi, un LLM local propose aussi Mettre à jour… (la version précédente est gardée en secours), Dossier des modèles… et Désinstaller…, qui retire le programme, la commande, le service et les réglages, mais jamais les modèles. Les LLM locaux que tu as installés toi-même sont affichés, mais jamais modifiés.

Démarrer et arrêter avec les agents

Connecte une fois un agent à un LLM local, puis démarre simplement l'agent — même app fermée ou après un redémarrage. Son LLM local démarre avec lui, et quand le dernier agent qui l'utilise se termine, le LLM s'arrête environ cinq secondes plus tard, ce qui libère à nouveau sa mémoire graphique.

Un petit service d'arrière-plan s'en charge, ai-agents-map-providers.service. Il est mis en place avec la première connexion à un LLM local et retiré quand la dernière disparaît ou quand tu désactives Réglages › Démarrer les LLM locaux avec leurs agents.

Remarque KoboldCpp met quelques secondes à démarrer, plus longtemps que certains agents n'attendent. Il démarre donc à l'ouverture de session, et quand le dernier agent se termine, seul son modèle est déchargé.

Les détails d'un LLM local

Clique sur la carte d'un LLM local dans Configuration, ou clic droit sur sa boîte de la carte › Détails. Sous les tuiles (modèles, agents, adresse) viennent les mêmes cartes repliables que pour les agents : Utilisation et jetons — ce que tes agents ont envoyé par lui ces derniers jours, par agent et par modèle, d'après les propres chiffres de session des agents et associé par nom de modèle —, puis État, Gestion des risques, Ce que veulent dire les mots et Configuration.

Mémoire GPU et libérer la mémoire GPU

Dans la carte GPU au-dessus de la carte, Mémoire GPU montre combien est utilisé, réparti entre LLM locaux, bureau et applications, et libre ; Activité GPU montre la charge, la température et la puissance. La boîte de chaque LLM local montre combien de mémoire il occupe, et les modèles chargés reçoivent un point vert.

Clic droit sur un LLM local pour Démarrer, Arrêter, le démarrage à l'ouverture de session et Libérer la mémoire GPU : ses modèles sont déchargés, il continue de tourner et en recharge un quand on le lui demande.

Un LLM local qui occupe de la mémoire GPU reçoit un bouton d'arrêt rouge sur sa case. Il demande d'abord : Libérer la mémoire GPU décharge ses modèles ; Arrêter l'arrête. Pour LM Studio, le bouton est Arrêter le serveur : seul son serveur s'arrête, l'application reste ouverte avec ses modèles chargés. Un modèle chargé par un LLM local mais utilisé par aucun agent lui est relié par une ligne claire continue.

LM Studio peut être ouvert sans son serveur. Sa case affiche alors serveur arrêté avec un point jaune, les agents ne peuvent pas l'atteindre et son menu propose Démarrer le serveur (lms server start).

Utilisé par d'autres apps

Les LLM locaux ne servent pas qu'aux agents. Un plugin comme Video Trans, une app de chat ou ton propre script peuvent aussi leur envoyer des requêtes. L'app le remarque et le montre :

Un programme absent de la carte (ici curl) qui génère avec llama.cpp : la ligne et la boîte cyan (thème Tokyo Night). Le propre chemin de Claude Code vers opus reste dans la couleur d'accent.

  • Sur la carte, la ligne du LLM local vers le modèle avec lequel il génère devient épaisse et prend sa propre couleur, une lumière la parcourt, et la boîte du modèle reçoit bordure et point de cette couleur et dit qui l'utilise, par exemple utilisé · Video Trans.
  • Le menu contextuel du LLM local et sa page ⓘ Détails indiquent Utilisé par Video Trans · maintenant ou il y a combien de secondes il a servi pour la dernière fois.
  • La légende ⓘ montre les deux marques.

L'app regarde lesquels de tes propres programmes ont une connexion ouverte vers le LLM local. Elle ne lit jamais ce qu'ils envoient. Un plugin apparaît sous son propre nom, un agent sous le sien, et tout le reste sous le nom de son programme. L'app elle-même et LLM Monitor, qui ne lisent que l'état, ne comptent pas.

Remarque La lumière ne se voit que pendant que le programme génère et s'éteint environ dix secondes après sa dernière requête. Un programme ouvert mais inactif — Video Trans sans parole à traduire — ne montre rien. Un programme reste dans le menu une demi-minute après sa dernière requête.

Modèles

Clic droit sur un LLM local installé › Modèles…, ou clique sur Ajouter un modèle dans Configuration. La page a une liste à gauche et le modèle choisi à droite, dans trois onglets.

Récupérer depuis Hugging Face : ce que sait faire un modèle et quelle taille tient dans ta carte graphique.

Récupérer depuis Hugging Face

Parcours les modèles de chat GGUF populaires ou fais une recherche. Chaque résultat montre l'auteur, la taille, les téléchargements, les j'aime, l'ancienneté et ce qu'il sait faire : Vision, Outils, Raisonnement, MTP. La page du modèle montre les paramètres, l'architecture, le contexte, la licence et la fiche du modèle. Ce que signifie le nom explique les parties du nom, comme 35B-A3B ou Q4_K_M.

Options de téléchargement liste chaque taille avec la façon dont elle tient : dans la carte graphique, en partie en mémoire vive (fonctionne, mais plus lentement) ou probablement trop grande. Le meilleur choix est déjà fait ; Télécharger le récupère dans le dossier des modèles.

Les téléchargements tournent en arrière-plan et apparaissent dans une bande en haut de la page principale. Si la connexion tombe, ils réessaient et reprennent. Si l'app a été fermée pendant un téléchargement, il est listé comme interrompu, avec Reprendre ou Abandonner.

Installés

Installés : contexte actuel, le meilleur pour ta carte et celui de l'entraînement ; ce que signifie le nom ; Retirer.

Chaque modèle montre sa taille, son fichier et son contexte — actuel, le meilleur pour ta carte et entraîné pour. Retirer demande d'abord et déplace les fichiers dans la corbeille, d'où tu peux les restaurer. Un modèle qui n'est qu'un lien ne perd que le lien.

Taille de contexte

Le contexte, c'est la quantité de texte que le modèle peut garder en tête à la fois. L'app calcule, à partir du fichier du modèle lui-même, le plus grand contexte qui tient dans ta carte graphique. Définir le contexte l'écrit dans les réglages du LLM local, avec sauvegarde et Annuler. Les agents ont besoin d'un contexte assez grand ; quand tu connectes un agent à un modèle LM Studio sans contexte défini, le meilleur est défini dans la même étape.

Sur ce PC

Liste les fichiers GGUF que le LLM local ne lit pas encore — dans son dossier des modèles, dans ceux des autres LLM locaux, dans ~/Downloads et dans ~/Models. Ajouter en fait son modèle sans deuxième copie (par un lien), sauf pour Ollama, qui importe sa propre copie.

Déplacer et supprimer des modèles

Clic droit sur un modèle de llama.cpp, KoboldCpp ou LM Studio › Déplacer vers…, ou fais glisser la boîte du modèle sur le dossier d'un autre LLM local. Tu vois d'abord combien est déplacé et quel agent utilise le modèle. Annuler remet les fichiers en place. Supprimer… demande d'abord et déplace les fichiers dans la corbeille.

Un seul dossier des modèles

Réglages › Dossier des modèles fixe un dossier pour les modèles de tous les LLM locaux. Ranger les modèles… montre à l'avance comment les fichiers seraient classés (<dossier>/<éditeur>/<modèle>/), et rien ne change tant que tu n'appuies pas sur Ranger. Avec Les anciens chemins restent valables (activé par défaut), un lien reste à chaque ancien emplacement. Annuler le dernier rangement remet tout en place.

Attention Lors d'un déplacement vers un autre disque, les modèles sont d'abord copiés et les originaux ne sont retirés qu'une fois la copie terminée. Vérifie qu'il y a assez de place libre sur la destination ; sinon, l'app refuse le déplacement.

Connecter en dessinant

Appuie sur une boîte de la carte et fais glisser jusqu'à une autre pour les connecter. Chaque modification montre, avant d'écrire, exactement quelles lignes de quel fichier changent, fait une sauvegarde et peut être annulée depuis la barre qui suit.

Agent ↔ LLM local

Fais glisser d'un agent vers un LLM local ou l'inverse. Choisis le modèle et si l'agent l'utilise tout de suite. Pour modifier une connexion, sélectionne son agent (ou clique sur la ligne) : chaque ligne qu'on peut déplacer ou retirer montre un crochet orange à son extrémité. Fais glisser le crochet vers un autre LLM local — ou dans le vide pour la retirer ; survoler un crochet indique ce que fait le glisser. Avec un agent sélectionné, un clic sur un modèle d'un LLM local connecté fait de ce modèle celui de l'agent.

Agents pris en charge : Hermes, Pi, Oh My Pi, OpenCode, OpenClaw et DeepSeek Harness.

Agent ↔ serveur MCP

Fais glisser d'un agent vers un serveur MCP. Les réglages du serveur sont copiés dans le format propre à cet agent. Pris en charge : Claude Code, Codex, Copilot, Crush, Cursor, Gemini, Grok, Hermes, Muse, Oh My Pi, OpenClaw, OpenCode et Pi. Les fichiers de réglages pouvant contenir des clés sont toujours écrits de façon que toi seul puisses les lire.

Agent ↔ dossier de skills

Fais glisser d'un agent vers un dossier de skills. Pi et Hermes reçoivent le dossier dans leurs réglages ; tout autre agent reçoit un lien par skill dans son propre dossier de skills. Un dossier qu'un agent lit de lui-même (la plupart lisent ~/.agents/skills) ne peut pas être retiré à ce seul agent.

Quand une connexion échoue

Juste après l'écriture d'une connexion, l'app vérifie si elle fonctionnera : si un LLM local est installé et propose le modèle, si un serveur MCP répond, si les liens des skills sont intacts. Une connexion échouée reste sur la carte sous forme de ligne rouge en pointillés avec un ! ; une connexion avec seulement des avertissements est jaune en pointillés. Clique sur la ligne ou son ! pour des conseils :

  • Tester à nouveau la vérifie encore ; si elle passe, la ligne redevient normale.
  • Réessayer… ouvre la page de connexion pour une connexion qui n'a jamais été écrite.
  • Supprimer la connexion la retire.

Configurer un serveur

La page du serveur dit qui l'a fait et à quel point c'est vérifié, ce qu'il fait (avec des choses que tu peux demander à un agent), comment il tourne — comme programme via npx, uvx ou Docker, ou comme service web — et ce dont il a besoin, comme un dossier ou une clé API avec un lien pour l'obtenir. En dessous, Configurer :

  1. Remplis les champs dont le serveur a besoin.
  2. Coche les agents qui doivent le recevoir.
  3. Clique sur Tester pour demander ses outils au serveur.
  4. Clique sur Ajouter : tous les agents cochés sont écrits d'un coup, avec un aperçu et un Annuler.

Remarque Les valeurs secrètes, comme les clés API, sont passées dans l'environnement ou dans des en-têtes, jamais dans une ligne de commande où d'autres utilisateurs de l'ordinateur pourraient les lire. Un serveur qui aurait besoin d'un secret dans sa ligne de commande doit être configuré à la main.

Gérer les serveurs

ⓘ Détails sur la carte d'un serveur MCP montre le fichier de réglages de chaque agent, la commande ou l'adresse et, à la demande, les outils du serveur ; les valeurs des clés ne sont jamais affichées. Retirer le retire de tous les agents. Les serveurs restent dans la liste quand plus aucun agent ne les utilise, pour qu'une ligne puisse les reconnecter.

Quand une version plus récente d'une app qui fournit un serveur MCP apparaît dans ~/Applications, un conseil le signale. Mettre à jour… décompresse la nouvelle version, y fait pointer chaque agent et garde l'ancienne sept jours en sauvegarde. Rechercher des mises à jour (sous Sur ce PC) le fait pour toutes ces apps à la fois après ton clic : il regarde dans les nouvelles versions, propose toutes les mises à jour dans un aperçu avec une sauvegarde et un Annuler, puis teste chaque serveur mis à jour ; un conseil nomme ceux qui ne répondent pas.

Skills

Une skill est un dossier d'instructions qui apprend à un agent une tâche précise. + Skills ouvre une page organisée comme celle des MCP.

Trouver des skills

  • Sur ce PC : des dossiers de skills apportés par des apps et qu'aucun agent ne lit encore.
  • Depuis le web : une recherche dans l'annuaire skills.sh, sur un autre site avec la même API ou dans un dépôt GitHub de skills. Une skill est récupérée depuis son dépôt GitHub dans un dossier de ton choix, par défaut ~/.agents/skills.

Attention Les skills peuvent contenir des scripts qu'un agent pourra exécuter plus tard. La page montre le dépôt et liste les scripts avant toute récupération — jette-leur un œil.

Dossiers de skills

Chaque carte de dossier de skills montre ses skills et les agents qui le lisent. Un dossier partagé par des liens n'apparaît qu'une fois, là où il se trouve vraiment. ⓘ Détails liste chaque skill avec sa description et la façon dont chaque agent reçoit le dossier.

Espace disque

Espace disque : agents, LLM locaux et modèles montre combien de place prend ta configuration IA et où. Il est mesuré en arrière-plan à chaque ouverture de l'aide (de nouveau après dix minutes ou avec Mesurer à nouveau) et seulement lu — rien n'est supprimé d'ici. Le titre montre toujours les totaux sur une ligne (Agents · LLM locaux · Modèles · Au total) ; un clic replie la section. Disques, Agents, LLM locaux et Dossiers de modèles commencent repliés, chacun avec son total et les éléments les plus gros ; un clic les ouvre.

Les totaux, la part de l'IA dans tout l'espace disque et les sections repliées avec leurs totaux.

  • Tuiles : tout ensemble, puis programmes des agents, données des agents (réglages, sessions, historique), LLM locaux (programmes et leurs propres données) et modèles.
  • Barre : tout l'espace des disques où se trouve la configuration IA. Les parties colorées sont la configuration IA, le gris est tout le reste sur ces disques et le reste vide est libre ; la ligne au-dessus donne la part de l'IA en pourcentage. Survole la barre pour les tailles exactes.
  • Disques : chaque disque avec ce que la configuration IA y occupe et ce qui reste libre.
  • Agents, LLM locaux, Dossiers de modèles : une ligne chacun, les plus gros d'abord. Ouvre une ligne pour voir chaque dossier avec sa taille et son nombre de fichiers, et l'ouvrir dans le gestionnaire de fichiers. Un dossier de programme dit combien de versions sont gardées ; pour un agent avec plusieurs anciennes versions dans mise, une astuce mentionne mise prune, qui retire celles qui ne servent pas. Un dossier de modèles dit quels LLM locaux l'utilisent, ou qu'il ne contient que des liens vers des modèles d'un autre dossier.

Astuce Les programmes peuvent être réinstallés et les modèles retéléchargés ; les données des agents contiennent tes sessions et tes réglages. Quand la place manque, regarde d'abord les anciennes versions de programmes et les modèles que tu n'utilises plus.

Les tailles sont de l'espace disque : un fichier conservé à deux endroits compte une fois, et les liens ne sont pas suivis.

Bilan de santé et de sécurité

Un agent de programmation lit et écrit des fichiers et exécute des commandes sur ton ordinateur. Ce qu'il peut faire sans te demander se trouve dans ses propres réglages, avec des mots différents pour chaque agent. Le Bilan de santé et de sécurité rassemble tout cela : sur la page de détails de chaque agent et de chaque LLM local, quatre cartes montrent s'il fonctionne, ce qu'il peut faire, ce que cela signifie en mots simples et ce qui réduit le risque.

Modifier un réglage

  1. Clique sur un réglage pour l'ouvrir. Tu vois ce qu'il contrôle et chaque choix avec son risque ; celui qui est utilisé porte la marque Utilisé, le choix plus sûr recommandé.
  2. Clique sur Utiliser … à côté d'un choix ou sur Réduire … à côté d'un risque. Une page montre la modification en mots (avant → après), le risque avant et après, et Ce qui change : les lignes du fichier de réglages de l'agent.
  3. Clique sur Modifier. Le fichier est sauvegardé et écrit ; une notification propose Annuler pendant 30 secondes. L'agent utilise le nouveau réglage à son prochain démarrage.

Remarque Seule cette clé change ; les commentaires et tout le reste du fichier restent tels quels. Un réglage qui demande plus d'une ligne dans un fichier — comme Hermes qui exécute ses commandes dans Docker — est montré et expliqué, avec l'endroit où le modifier, mais n'est pas modifié d'ici.

Maîtriser le risque

Le niveau de risque est le point le plus sérieux que trouve la carte :

  • Risque élevé — il peut faire des choses sérieuses sans demander : exécuter n'importe quelle commande, ou travailler sans sandbox et sans questions. Acceptable dans un conteneur jetable ou une machine virtuelle ; sur ton propre PC, fais-le demander d'abord.
  • Risque moyen — certaines choses se font sans demander, comme modifier des fichiers du projet, ou une revue automatique décide à ta place.
  • Risque faible — il demande avant tout ce qui compte, ou ne peut pas le faire du tout.

Bonnes habitudes, quels que soient les réglages :

  • Demander d'abord pour les commandes sur ton propre ordinateur ; autorise des commandes isolées et anodines (comme git status) avec une règle d'autorisation plutôt que tout le shell.
  • Active la sandbox là où l'agent en a une (Claude Code, Codex, Cursor CLI) et laisse le réseau désactivé à l'intérieur tant qu'aucune tâche n'en a besoin.
  • Démarre les agents dans le dossier du projet, pas dans ton dossier personnel, et garde clés et mots de passe à l'écart.
  • Peu de serveurs MCP : seulement ceux que tu utilises et en qui tu as confiance. Chacun tourne avec tes droits.
  • Le travail sans surveillance (mode contournement, « YOLO », Pi avec tous les outils) se fait dans un conteneur ou une machine virtuelle.
  • Les LLM locaux sur 127.0.0.1 : leurs serveurs n'ont pas de mot de passe.

Attention Une revue automatique (le mode auto de Claude Code, assisted de Copilot, auto-review de Cursor, smart de Hermes) est une seconde IA qui juge chaque étape. Elle épargne des questions, mais c'est un jugement, pas un mur.

Les mots expliqués

Ce que change une sandbox : les commandes n'atteignent que le dossier du projet et ce que tu autorises.

Sandbox
Un espace isolé où tournent les commandes de l'agent. À l'intérieur, une commande ne peut toucher que le dossier du projet (et ce que tu autorises) — pas le reste de ton dossier personnel, tes clés SSH ou les données du navigateur, et souvent pas internet. Sans sandbox, une commande de l'agent peut faire tout ce que tu peux faire.
Approbation (demander d'abord)
Avant que l'agent ne modifie un fichier ou n'exécute une commande, il montre ce qu'il veut faire et attend ton oui ou ton non. Moins il peut faire sans demander, plus tu gardes le contrôle — et plus souvent il te demande.
Règles d'autorisation et d'interdiction
Des listes de commandes ou d'outils que l'agent peut utiliser sans demander (autoriser) ou jamais (interdire). Interdire l'emporte sur autoriser. Une règle qui autorise n'importe quelle commande shell désactive l'approbation pour le shell.
Dossier de confiance
Un dossier dans lequel tu as dit que l'agent peut travailler. Là, il utilise aussi les propres instructions et réglages du dossier, qui peuvent venir de quelqu'un d'autre quand tu clones un projet.
Accès au réseau
Si les commandes peuvent atteindre internet. Du code qui lit tes fichiers et peut envoyer des données pourrait les divulguer ; installer des paquets a aussi besoin du réseau.
Contournement (« YOLO »)
Tout sans demander et sans limites. Seulement pour une VM ou un conteneur jetable.
Revue automatique
Un second modèle d'IA laisse passer les actions anodines et demande pour le reste.
Injection de prompt
Des instructions cachées dans une page web, un fichier ou la réponse d'un outil, qui essaient de faire faire à l'agent quelque chose que tu n'as pas demandé. Demander d'abord, une sandbox et pas de réseau les arrêtent.
Masquer les secrets
Un texte qui ressemble à un mot de passe, un jeton ou une clé est masqué avant que le modèle ne le voie ou qu'il n'atterrisse dans un journal.
Outils
Ce que l'agent peut faire tout court : lire, écrire, exécuter des commandes, chercher sur le web. Un outil qu'il n'a pas ne peut pas être détourné.
Serveur MCP
Un petit programme qui donne des outils supplémentaires à l'agent. Il tourne en tant que toi, avec tes droits.

Modules

Tout ce qu'Asterism comprend d'un agent ou d'un fournisseur de LLM est un adaptateur : comment il est trouvé et installé, ses sessions, ses réglages de sécurité, ses serveurs MCP et ses skills. Dans Asterism, chaque adaptateur est un module : les paquets les apportent tous, signés et désactivés, et tu actives ceux que tu utilises. Les modules apportent aussi de nouveaux agents, de nouveaux fournisseurs et des fonctions au-delà des chiffres, comme Insights (sujets des sessions et un résumé par Claude). Le plugin AI Agents Map a les adaptateurs intégrés et n'a pas de modules.

Configurer Asterism

Un Asterism neuf s'ouvre sur sa page d'accueil. Chaque agent et LLM local qu'Asterism connaît est une carte avec sa propre icône, en trois groupes : Agents IA, LLM locaux et Fournisseurs en ligne (les noms d'Anthropic, d'OpenAI et des autres sur la carte). Chaque carte dit si le programme est là :

  • Installé (vert) — trouvé de la même façon que la carte le trouve ; la carte est déjà cochée ;
  • Utilisé auparavant — pas installé maintenant, mais ses réglages sont toujours là ;
  • Non installé — coche-le pour l'installer ensuite depuis sa carte.

La page d'accueil : les programmes trouvés viennent en premier et sont cochés.

Clique sur une carte (ou appuie sur Espace dessus) pour la cocher ou la décocher ; une carte cochée a une bordure bleue et une coche. Activer (avec le nombre de cartes cochées) les charge et montre la carte ; si tu as coché des programmes qui ne sont pas installés, Configuration s'ouvre : ⋯ sur leurs cartes › Installer…. Plus tard démarre avec une carte vide. Tant que rien n'est activé, Asterism se rouvre sur la page d'accueil à chaque démarrage. Ensuite, les mêmes cartes se trouvent dans Configuration (le bouton de l'en-tête), où agents et fournisseurs s'activent et se désactivent à tout moment.

La page des modules

Ouvre-la avec le bouton pièce de puzzle de l'en-tête, depuis Réglages › Modules ou depuis n'importe quel conseil « module disponible ». Elle montre, dans des cartes de groupe repliables qui commencent ouvertes :

  • Suggérés pour ce PC — un module dont l'agent ou le fournisseur est installé ici mais pas encore affiché ;
  • Modules installés — activé, désactivé ou non chargé avec la raison (par exemple un fichier modifié) ; les agents et les fournisseurs séparés par une ligne ;
  • Disponibles — le reste des modules du catalogue ;
  • Intégré à Asterism — les agents et fournisseurs qu'aucun module installé n'apporte (quand tu lances Asterism depuis son dossier source sans modules).

Modules installés : activés ou désactivés, avec Installer et Désinstaller pour le programme.

La carte d'un agent ou d'un LLM local activé a Installer et Désinstaller pour le programme lui-même (celui qui ne s'applique pas est grisé), et chaque carte avec une page d'accueil a un bouton globe qui l'ouvre dans ton navigateur.

La recherche trouve les noms, les descriptions et ce qu'un module lit ; les filtres au-dessus limitent la liste aux agents, fournisseurs, fonctions, aux installés ou à ceux qui ont une mise à jour. Clique sur une carte pour ses détails : ce qu'il lit, ce qu'il envoie, ce qu'il peut faire et son niveau de confidentialité.

Installer, activer et désactiver, mettre à jour, retirer

Installer (ou Obtenir le module) montre d'abord ce que le module lit, envoie et peut faire ; ce n'est qu'après ton accord qu'il est téléchargé, vérifié et activé. Désactiver et Activer agissent aussitôt, sans redémarrage : ses agents, fournisseurs, sections et cartes apparaissent ou disparaissent partout. Mettre à jour le remplace par la version plus récente du catalogue après vérification de la nouvelle ; Retirer le déplace dans la corbeille. Installer depuis un fichier… prend un zip de module que tu as téléchargé toi-même ; les mêmes vérifications s'appliquent.

Seulement de l'auteur. Asterism ne charge que des modules signés par Uwe Bruckhaus (empreinte de la clé SHA256:e5cC634Ke3Our5LAeSc88qs22NKZEHTncBW5Ig3amWQ). Avant que quoi que ce soit d'un module ne tourne, la signature est vérifiée avec ssh-keygen d'OpenSSH, chaque fichier est comparé à sa somme SHA-256, et aucun fichier ne doit avoir été ajouté. Un téléchargement doit en plus correspondre à la somme SHA-256 du catalogue signé.

Un module ne peut jamais faire plus que ce que permet son niveau. Ajouter un agent ou un fournisseur, ou installer un programme, sont des permissions séparées que sa carte nomme.

Un module d'agent décrit son agent sous forme de données (un fichier nommé agent.toml) ; la plupart n'apportent aucun code, et la page du module le dit : N'apporte pas de code ou, pour les quelques agents qui en ont besoin (par exemple leur propre base de sessions), Des données sur l'agent, et un peu de code pour ce que les données ne peuvent pas dire.

Un nouvel agent sur ton ordinateur

Quand tu installes un agent qu'Asterism ne connaît pas encore, il regarde dans le catalogue (Réglages › Chercher des modules en ligne, activé par défaut : la liste est lue sur GitHub toutes les quelques heures et seule la requête est envoyée). Si un module connaît cet agent, Mises à jour et suggestions (le ! de l'en-tête) le dit (« Kilo Code est sur ce PC mais pas sur la carte »), et une carte apparaît sous Suggérés pour ce PC ; un clic l'installe. S'il n'y a pas encore de module, les détails de l'agent le disent, avec un lien pour en demander un.

Créer un module

Un nouveau LLM local ou un nouvel agent n'a besoin que d'un module : Asterism construit sa carte, sa boîte et ses lignes sur la carte, ses détails, la page Modèles et la page Sécurité à partir de ce que le module en dit. Si tu sais un peu programmer, pars des modèles du dépôt d'Asterism (templates/, expliqués dans docs/addons.md) : un fichier pour un LLM local, un fichier de faits pour un agent. Envoie le module à github.com/uBruckhaus/asterism-addons ; une fois relu et signé, il apparaît pour tout le monde sous Disponibles.

Confidentialité et sécurité

  • Aucun droit d'administrateur pour l'app. Elle ne tourne jamais en root et ne voit jamais de mot de passe. Installer un agent fourni comme paquet du système (comme Hermes ou OpenClaw) lance le gestionnaire de paquets du système avec sudo dans un terminal que tu vois, après t'avoir montré la commande.
  • Aucun identifiant lu. Elle lit les réglages des agents, mais jamais leurs fichiers d'identifiants. Qu'un agent soit connecté se voit à l'existence d'un tel fichier. Les valeurs des clés et des en-têtes ne sont jamais affichées.
  • Aucune conversation lue. Les chiffres d'utilisation ne sont lus que comme des nombres et des durées.
  • Le réseau seulement quand tu le demandes — chercher ou installer des modèles, des serveurs MCP ou des skills, tester un serveur —, plus une vérification des mises à jour toutes les quelques heures.
  • Téléchargements vérifiés. Les programmes ne sont installés que si le téléchargement correspond à la somme publiée par leur version.
  • Aperçu et Annuler. Chaque modification des réglages d'un autre programme est montrée avant, sauvegardée et peut être annulée. Les réglages pouvant contenir des clés sont écrits lisibles par toi seul.
  • Encadré. Chaque programme tourne sans shell, et chaque réponse est lue avec une limite de taille et de temps.

Le README de chaque dépôt liste en entier ce qui est lu, démarré et écrit.

Glossaire

Approbation
Un agent demande avant de modifier un fichier ou d'exécuter une commande (voir Les mots expliqués).
Contexte
Combien de jetons de texte un modèle peut garder en tête à la fois.
GGUF
Le format de fichier de modèles utilisé par llama.cpp, LM Studio, Ollama et KoboldCpp.
Injection de prompt
Des instructions cachées dans une page, un fichier ou la réponse d'un outil qui essaient d'orienter un agent.
Quantification
Stocker un modèle avec moins de bits par poids (par exemple Q4_K_M, environ 4,8 bits) pour qu'il soit plus petit, avec une faible perte de qualité.
Mélange d'experts
Un modèle où seule une partie des paramètres travaille pour chaque jeton (35B-A3B : 35 milliards au total, 3 milliards actifs), ce qui le rend rapide pour sa taille.
Sandbox
Un espace isolé où tournent les commandes d'un agent, qui n'atteignent que le dossier du projet et ce qui est autorisé.
Jeton
Un morceau de texte, environ les trois quarts d'un mot, que les modèles lisent et écrivent.
Service utilisateur
Un programme d'arrière-plan que systemd démarre pour ton utilisateur seulement, sans droits d'administrateur.
